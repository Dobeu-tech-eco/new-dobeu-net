## 2026-05-26 - [CRITICAL] Multiple vulnerabilities in Lead Capture endpoint
**Vulnerability:** Found an IP Spoofing vulnerability that could bypass the memory-based rate limit because the `x-forwarded-for` header was reading the first element, which can be easily spoofed by attackers by prepending to the header. Found an OOM / Memory Leak vulnerability on the same rate limiting implementation because `ipBuckets` Map had no size constraint and could grow indefinitely if an attacker uses numerous different IP addresses. Lastly, found a payload size DoS vulnerability because string inputs in `LeadSchema` lacked `.max()` constraints.
**Learning:** In-memory rate limiting requires bounded maps to avoid memory leaks. The `x-forwarded-for` header values can be spoofed by attackers and the rightmost value is typically the most reliable since it is appended by the load balancer or proxy right before routing the request. Using Zod string without `.max()` allows attackers to submit gigantic payloads which can crash the server via OOM.
**Prevention:** Add hard `.max()` constraints on all Zod string types. For in-memory maps, always add a size limit check (e.g., `if (map.size > X) map.clear();`). Use `request.headers.get("x-forwarded-for")?.split(",").pop()?.trim()` or `x-real-ip` to fetch the client IP in standard proxy configurations.

# Step 6 — Copy editing

Installed copy-editing 2.2.0; mode B, restoring the existing personal voice. Read seven sweeps and reference checklist. Inputs: end-state criteria, scout surface, confirmed context, step 5 draft and earlier findings. Recommendations only.

## Seven sweeps, in order
1. Clarity: retain exact headline; named projects make its meaning concrete. Tighten project introduction to “Explore RouteReady, Chima Comics, Dobeu.space, and Ikram & Co.” The second draft sentence repeated the invitation without adding useful information.
2. Voice: retain “I’m Jeremy” and broad bio. Use personal invitation rather than sales-team language. Keep the user-mandated “We build” headline; it is not evidence of staffing.
3. So what: project descriptions explain what visitors can explore; CTA helper explains what to send. Technical stack claims on /website-package add little to a collaboration invitation.
4. Prove it: no metrics, credentials or testimonials introduced. Existing package timeframe/price need confirmation before rebrand launch; repository copy alone does not verify current availability. Privacy “reply only” wording needs review against Apollo/Customer.io fan-out.
5. Specificity: project names supply specificity while bio intentionally stays vague. Do not add career facts to satisfy a generic copy rubric.
6. Emotion: curiosity and an invitation are enough. Do not manufacture urgency, painful founder stories or fear of missing out.
7. Risk/next step: retain form receipt wording after durable acceptance. A conversation does not promise a partnership. State any paid scope separately before work begins.

After each proposed edit, earlier sweep constraints were rechecked. No additional application edit made.
